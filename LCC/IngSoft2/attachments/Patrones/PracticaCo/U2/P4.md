# Mantenimiento de catálogos

## Enunciado

Una compañía de venta por correo ha decidido establecer una serie de almacenes regionales relativamente autónomos. Cada uno de ellos adquiere responsabilidad local para la gestión de catálogos y el procesamiento de pedidos. Cada almacén mantiene catálogos lo más adecuados posibles al mercado local. La línea especíﬁca de productos que gestiona cada almacén pude cambiar de una región a otra; además, la línea de productos gestionada por una región dada tiende a actualizarse una vez al año según los gustos de los consumidores. La compañía desea tener un sistema de seguimiento de catálogos y pedidos común para todos los almacenes. Las funciones claves del sistema incluyen:
— Gestionar mercancías al entrar al almacén, expedidas por distintos proveedores.
— Gestionar los pedidos según se reciben de una organización de venta a distancia, central pero remota; los pedidos también pueden recibirse por correo, y se procesan localmente.
— Gestionar los pedidos de informes hechos por los clientes.
— Generar listas de embalaje, utilizadas para dirigir al personal del almacén en la confección y despacho de un pedido.
— Generar facturas y controlar las facturas recibidas.
— Generar peticiones de suministro y controlar las facturas a pagar.
— Utilidad de generación de informes general y abierta.

Aplicar el patrón Composite. Hacerlo para deﬁnir con detalle la estructura de los catálogos. Cada producto ofertado en un catálogo tiene las siguientes características: nombre, código, descripción, varios niveles de secciones (por ejemplo, Ferretería, Tornillos y Bulones, Tornillos, Tornillos de acero, Tornillos de 1,5mm, etc.), precio, marca, color, etc.

Aplicar el patrón Iterator para recorrer la estructura de un catálogo.

## Documentación

| Pattern | EstructuraCatálogo |
|---|---|
| **based on** | Composite |
| **because** | - Permite tratar de forma uniforme productos individuales y secciones que agrupan (sub)secciones y productos, anidando secciones en varios niveles sin límite |
| **where** | Component **is** Componente<br>Leaf **is** Producto<br>Composite **is** Sección<br>Composite **is** Catálogo<br>Operation() **is** mostrar()<br>Add() **is** agregarHijo()<br>Remove() **is** eliminarHijo()<br>GetChild() **is** obtenerHijos() |

| Pattern | RecorridoCatálogo |
|---|---|
| **based on** | Iterator |
| **because** | - Permite recorrer todos los componentes de un catálogo sin exponer su estructura interna (árbol de secciones y productos) |
| **where** | Iterator **is** Iterador<br>ConcreteIterator **is** IteradorNormal<br>Aggregate **is** Componente<br>ConcreteAggregate **is** Sección<br>ConcreteAggregate **is** Catálogo<br>CreateIterator() **is** crearIterador()<br>First() **is** primero()<br>Next() **is** siguiente()<br>IsDone() **is** finalizó?()<br>CurrentItem() **is** actual() |
