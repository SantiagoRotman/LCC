# Plan de cuentas

## Enunciado

Un plan de cuentas de una contabilidad está formado por grupos de cuentas dentro de los cuales puede haber otros grupos de cuentas o cuenta reales. Las cuentas reales contienen asientos. Tanto a los grupos de cuentas como
a las cuentas se los denomina genéricamente cuentas. Las cuentas y asientos tienen un saldo, pueden borrarse, tienen un nombre, descripción y fecha. Los asientos tienen una cuenta de origen (que es de la cual forman parte) y una
cuenta de destino, el saldo puede estar en el debe o en el haber. El saldo de una cuenta se calcula en base al saldo de cada uno de los asientos que la conforman; el saldo de un grupo de cuentas se calcula en base al saldo de
cada una de las cuentas que lo forman. Borrar una cuenta signiﬁca borrar todo lo que contiene.

1. Aplique y documente el patrón Composite para estructurar el plan de cuentas.
2. Explique como re-implementaría las funciones principales de cada participante del punto anterior.
3. Aplique y documente el patrón Visitor para visualizar el plan de cuentas y guardarlo y recuperarlo de una base de datos. Los grupos de cuentas se visualizan en forma de árbol, en tanto que cuando el usuario hace doble click sobre una cuenta real se listan todos sus asientos en una ventana separada.
4. Explique como re-implementaría las funciones principales de cada participante del punto anterior.
5. La empresa que desarrolla el software de contabilidad planea venderlo en Argentina, Perú e Italia. En cada país los formularios como Factura, Cliente y Remito son ligeramente diferentes. Aplique y documente el patrón Abstract Factory para internacionalizar el sistema.

## Documentación de patrones

Pattern: Cuentas
Based on: Composite
Because:
Where:
    - Cuenta is Componente
    - GruposDeCuentas is Composite
    - CuentaReal is Leaf
    - agregarCuentaHija() is add()
    - eliminarCuentaHija() is remove()
    - obtenerCuentaHijo is getChild()
    - calcularSaldo() is operation()

Pattern: Visualizador
Based on: Visitor
Because:
Where:
    - Visualizador is Visitor
    - VisualizadorArbol is ConcreteVisitor1
    - Cuenta is Element
    - GruposDeCuentas is ConcreteElementA
    - CuentaReal is ConcreteElementB
    - visitarGrupoDeCuentas() is visitConcreteElementA()
    - visitarCuentaReal() is visitConcreteElementB()
    - aceptar() is accept()

Pattern: Fábrica de Formularios
Based on: Abstract Factory
Because:
Where:
    - FábricaDeFormularios is AbstractFactory
    - FábricaDeFormulariosArgentina is ConcreteFactory1
    - FábricaDeFormulariosPeŕu is ConcreteFactory1
    - FábricaDeFormulariosItalia is ConcreteFactory1
    - Factura is AbstractProductA
    - Cliente is AbstractProductB
    - Remito is AbstractProductC
    - FacturaArgentina is ProductA1
    - FacturaPerú is ProductA2
    - FacturaRemito is ProductA3
    - ClienteArgentina is ProductB1
    - ClientePerú is ProductB2
    - ClienteRemito is ProductB3
    - RemitoArgentina is ProductC1
    - RemitoPerú is ProductC2
    - RemitoRemito is ProductC3
    - crearFactura() is createProductA()
    - crearCliente() is createProductB()
    - crearRemito() is createProductC()
